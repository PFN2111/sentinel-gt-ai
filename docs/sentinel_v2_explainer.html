North star

A Tier 2 engineer stays in one local app. They drop in a historian CSV, the analytic name and their notes, and get a draft site report with the evidence beside it. They review, edit, and approve or correct it. The human makes the final call. They can also teach the app and retrain it here. Review and inference do not use the network.

  1. Drop in. CSV, analytic name, notes.
  2. Draft. Classifier, residual view, similar labeled cases, rule shadow, process steps, then Gemma 4 12B (or the template if the model fails its checks).
  3. Review. The report stays a draft until the engineer marks it. A disagreement, a low confidence, a novel pattern, or a residual contradiction asks for a person.
  4. Teach. Label the case and say why, add a process document, name a new signature, add a frame layout, or add an alert type.
  5. Retrain. Quick update in seconds, or a full TS Pulse fine-tune. Keep the new version only when held-out accuracy is not worse, including each frame and alert slice that has enough cases. Roll back in one click.

Pipeline

CSV→ features→ TS Pulse classifier and embedding+ TS Pulse residuals→ similarity and novelty→ rules shadow→ process knowledge→ Gemma prompt→ checks→ report→ review gate

Features

Fourteen canonical channels, 512 points (the whole record and a zoom). The encoder was fine-tuned on this layout. The frame models are 6B, 7EA, 7FA, 7HA, 9E, 9FA, 9HA, and Other / custom. Each model points at a tag layout in LAYOUTS plus a typical exhaust thermocouple count. That layout (or one added from Teach) puts the frame's exhaust and process tags onto those channels. Ring tags are ordered by the full sensor number, so TTXD_10 sits after TTXD_9. The case carries a frame model, from --frame, the dropdown, or the column names. Other / custom picks a layout or defines tags. Old layout ids on stored cases are mapped when the file is loaded.

Classifier, similarity, novelty

The fine-tuned TS Pulse encoder writes a 672-number embedding. A full retrain appends a small frame one-hot so the head, the similarity index, and the novelty radius can tell layouts apart. A frame gets its own novelty radius once enough validation cases exist; otherwise the shared radius is used. The similarity index cites the nearest labeled cases, including one the engineer just taught. If the nearest case is farther than the radius, the signature is novel and the action is escalate. One close engineer-labeled case can override the head.

Residuals

A second TS Pulse (reconstruction) scores each channel against its own baseline. It records which channel moved first, the size in physical units, whether neighbours followed, and whether the shape is a step, a freeze, spikes, or a sector. If those weights are missing, a robust-z score is used instead. doctor says which mode is active.

Cross-check

Each known signature has an expected residual pattern. The deterministic check returns supports, contradicts, or inconclusive. A single thermocouple stepping down while its neighbours stay flat contradicts a cold-sector signature and points at a sensor fault. A contradiction lowers confidence, is written into the concerns, and sets needs_human. Gemma is asked for the same verdict. If the two disagree, that disagreement is itself a review flag.

  • normal — no channel clearly abnormal
  • cold_spot_hardware — two or more adjacent exhaust TCs / zones cool together (sector), spread rises
  • tc_sensor_fault — one exhaust TC / zone moves alone (neighbours flat), or freezes, spikes or reads implausibly
  • combustion_instability — dynamics rise together with coupled exhaust / vibration / fuel movement
  • dynamics_probe_fault — the dynamics channel is abnormal alone (flatline, saturation, spikes), nothing coupled
  • hets_trip_hardware — a hot and a cold exhaust sector build up, then the unit trips
  • igv_lvdt_drift — IGV position departs from its load schedule; other channels steady
  • fuel_control_oscillation — fuel and load / exhaust oscillate together
  • novel_pattern — unlike any labeled case

Rules, knowledge, checks

The rule analyzers still run, in shadow. Their action is shown next to the learned action. Process maps (and documents added on the Teach page) are retrieved for the analytic, the signature, and whatever the residual check points to. Gemma must walk those steps. Every number in the narrative has to appear in the prompt. A novel case is never forced into a known class.

Teach the app, then retrain

Teach page

  • Cases. A labeled CSV plus a one-sentence why. The why is stored with the case and can be cited in a later prompt.
  • Documents. Markdown, text, or PDF. Sections are retrieved with the process maps.
  • Signatures. Name a new class, its action, and the residual pattern you expect.
  • Frames. Add a frame. Exhaust tags and process tags map onto the shared canonical channels. The shipped models are 6B, 7EA, 7FA, 7HA, 9E, 9FA, 9HA, and Other / custom. Each one points at a tag layout. A frame added here is stored with Teach, appears in the dropdown, and returns if that version is rolled forward.
  • Alert types. A new alert is a signature plus a process document. An alert with no built-in analyzer uses the generic fallback (learned model, similarity index, and that document). The report states which path ran.
  • Manage. See what was taught and roll a teach-state version back.

Retrain TS Pulse

Quick update refits the classifier head, rebuilds the similarity index from labeled cases, and recalibrates novelty. It does not change the encoder. On a laptop this is seconds once embeddings exist.

Full retrain fine-tunes TS Pulse on the synthetic set plus engineer cases, then runs the quick steps. On CPU that is on the order of 15–20 minutes. The job is a background process with a progress file, so leaving the page does not stop it.

Every result is a new version. It becomes the active model only when held-out action accuracy and signature accuracy are not worse than the current version, and no frame or alert slice with enough cases got worse. Force promote overrides that gate, and the reason is written to the train log. The Teach page and the report audit show the slice table. Roll back one version or restore any earlier version from the table. The same commands exist on the command line:

python sentinel_gt_ai.py train --quick --device auto
python sentinel_gt_ai.py train --full --device auto
python sentinel_gt_ai.py train --full --device cpu --force

--device auto uses the GPU when CUDA is available and retries the fine-tune on CPU if the GPU is missing or runs out of memory. gpu and cpu skip the choice.

Deploying to the Dell

  1. Copy sentinel_gt_ai.py (or this repository) onto the machine.
  2. python sentinel_gt_ai.py setup. Offline, point it at a USB copy: python sentinel_gt_ai.py setup --models-from E:\models.
  3. python sentinel_gt_ai.py.

python sentinel_gt_ai.py doctor checks the GPU, the llama.cpp build, Gemma, both TS Pulse snapshots, and the fine-tuned encoder. A missing model file prints python sentinel_gt_ai.py setup. A missing encoder prints python sentinel_gt_ai.py train --full --device auto.

The target Dell has a 6 GB NVIDIA GPU. device: auto offloads as many Gemma layers as free memory allows (about 28 of 48 when roughly 5.5 GB is free) and runs the rest on CPU. If the GPU init fails or runs out of memory, the report finishes on CPU and the audit says so. The build laptop used for these numbers is CPU-only. TS Pulse embedding is about a second or less per case. A Gemma report on that CPU is a few minutes; the table in the reports section has the measured times for this run.
